# 1. Analysis (Populated by RESEARCH mode)
The goal is to create a backend service that can:
1.  Accept a POST request with text content.
2.  Store this content securely with a unique identifier.
3.  Accept a GET request using the unique identifier to retrieve the content.
4.  Immediately delete the content after it has been retrieved once.

The chosen tech stack (FastAPI, Uvicorn, SQLAlchemy, SQLite) is well-suited for this. FastAPI will handle the web server and request/response logic. SQLAlchemy will manage the database interaction, and SQLite will be the simple, file-based database.

The project structure needs to be established to support this, including a `src` directory for our source code and a `pyproject.toml` for dependency management.

# 2. Proposed Solution(s) (Populated by INNOVATE mode)
The proposed solution is a modular FastAPI application.
- **`pyproject.toml`**: To manage dependencies using a modern standard. We will use `uv` for package management.
- **`src/main.py`**: The main application file containing FastAPI endpoints.
- **`src/database.py`**: Handles database connection setup and session management.
- **`src/models.py`**: Defines the `Note` database table schema using SQLAlchemy's declarative base.
- **`src/schemas.py`**: Defines Pydantic models for request and response data validation, ensuring data consistency.
- **`src/crud.py`**: (Create, Read, Update, Delete) Contains the functions that directly interact with the database, separating business logic from database logic.

This structure provides a clean separation of concerns, making the application easier to understand, maintain, and test.
